# Reproducing the dataset and the Stage 1 diagnostics

Everything here is **static analysis**. No sample is executed, loaded or
built. Samples live under `Samples/`, which is **not** in git; `Data/` is
generated and regenerated by the commands below.

## Prerequisites

- Python 3.10+ with `Tools/requirements.txt` installed.
- `.env` in the repo root with `MB_AUTH_KEY=...` (never commit or log it).
- `Samples/AsyncRAT`, `Samples/OtherMalwares` and `Samples/Benign` populated
  (MalwareBazaar downloads + `Data/BenignSources.csv` provenance).
- `rat_king_parser` installed for the labeler.

## Pipeline order

Run from the repository root.

```bash
# 1. Labels (parser + benign provenance); benign-only restores source/origin/kind
python3 Tools/Labeling/labeler.py
python3 Tools/Labeling/labeler.py --benign-only

# 2. Independent voters
python3 Tools/Voters/OwnYara/own_yara.py
python3 Tools/Voters/Elastic/elastic_voter.py
python3 Tools/Voters/Malpedia/malpedia_voter.py
python3 Tools/Voters/MalwareBazaar/mb_voter.py
python3 Tools/Voters/YARAify/yaraify_voter.py
python3 Tools/Voters/DIE/die_voter.py

# 3. Aggregate the evidence into final labels
python3 Tools/Aggregator/aggregator.py

# 4. TLSH + config clustering (cluster_id per sample)
python3 Tools/Clustering/clusterer.py

# 5. Scope audit: server/builder/stub/panel -> reference_only (metadata only)
python3 Tools/Audit/reference_only.py

# 6. Capability carvers (external references only)
python3 Tools/TypeRef/type_ref.py
python3 Tools/MemberRef/member_ref.py
python3 Tools/AssemblyRef/assembly_ref.py
python3 Tools/ImplMap/impl_map.py
python3 Tools/ImportTable/import_table.py
python3 Tools/Structure/structure.py

# 7. Import labels, clusters, carvers and structure into Data/*.db
python3 Tools/Importer/importer.py

# 8. Splits, then import the split assignments
python3 Tools/Splits/split.py
python3 Tools/Importer/importer.py

# 9. Feature matrix (vocabulary fitted on train only)
python3 Tools/Features/build_matrix.py

# 10. Baselines, LOCO and validity checks
python3 Tools/Models/baseline.py

# 11. Read-only dataset report
python3 Tools/Report/dataset_report.py
```

The importer consumes the `.done` markers written by the carvers and voters.
Re-running the importer without re-running the carvers fails on purpose; run
the carvers again (they are idempotent) before the second import.

## Historical AsyncRAT batches (MalwareBazaar full export)

`get_taginfo` only exposes a recent 500-row window. Historical samples come
from the full CSV export, selected by signature and TLSH distance:

```bash
python3 Tools/MBDownloader/mb_downloader.py \
  --from-export /tmp/opencode/mb_full.csv.zip \
  --batch 1 --per-year 50 --years 2020-2026 \
  --tlsh-threshold 100 --limit 350 --rate 10
```

- The archive is fetched at most once per hour; the URL contains the API key
  and is never logged. A fresh local archive is reused.
- Selection state is `Data/Exports/mb_full_selection.json` (sha256, year,
  first_seen, tlsh, file_name, batch, status). Batch 2 excludes batch 1.
- Candidates within TLSH distance 100 of an already selected sample are
  rejected (`tlsh_reject`); the ledger, signature and file-type filters are
  recorded in `downloads_rejected`.
- `check_ledger` fails the batch if a file on disk has no ledger row.

### Partial batches and resume

Every selection is written to the manifest **before** downloading. An
interrupted batch leaves its undownloaded entries with `status=selected`;
re-running the same `--batch N` resumes those entries first (up to `--limit`)
and never silently drops them. A paused batch (for example batch 2 after 31 of
350 downloads) can stay in the manifest indefinitely; later batches only
exclude entries that are already present, and files already on disk are
adopted by hash instead of re-downloaded.


Then rerun the pipeline (steps 1-11) and compare the gate and split validity
reported by `Tools/Report/dataset_report.py` and
`Data/Features/baseline_results.json`.

## Optional evidence voters

YARAify uses the same abuse.ch key as MalwareBazaar. Put either
`YARAIFY_AUTH_KEY` or `MB_AUTH_KEY` in `.env`; the voter prefers the former.
It never prints the key. Run at most one request per second:

```bash
python3 Tools/Voters/YARAify/yaraify_voter.py --delay 1.0
```

Detect It Easy (optional, for `obf_lvl`): use the official 4.1.0 Fedora 45 RPM
from `horsicq/DIE-engine` releases, the Fedora 45 `qt5-qtbase`/`qt5-qtscript`
runtime, and the `current-database` `db.zip` from `horsicq/Detect-It-Easy`.
`diec` works on Fedora 45 once `LD_LIBRARY_PATH` points at the extracted Qt5
libraries and `-D` points at the extracted `db` folder:

```bash
python3 Tools/Voters/DIE/die_voter.py --diec /path/to/diec-wrapper
```

If `diec` is not available, the voter records `obf_lvl=unknown`; never fake it.

In this run the verified CLI setup was: official DIE 4.1.0 Fedora 45 RPM
extracted under `/tmp/opencode/die_extract`, Fedora 45 `qt5-qtbase` /
`qt5-qtscript` extracted under `/tmp/opencode/qt5root`, the `current-database`
`db.zip` extracted under `/tmp/opencode/die_db`, and a wrapper at
`/tmp/opencode/diec` that sets `LD_LIBRARY_PATH` and passes
`-D /tmp/opencode/die_db/db`. The wrapper path is a local convenience, not a
repo dependency; any working `diec` with its database is accepted.

YARAify uses the **same abuse.ch key as MalwareBazaar** (`YARAIFY_AUTH_KEY`
first, `MB_AUTH_KEY` fallback). The fixed parser accepts both response shapes:
`data` as a dict with `tasks` (current) and `data` as a list (older). Family
names are read from `static_results[].rule_name`/`malpedia_family`,
`clamav_results[]` and `unpacked_yara_matches[]`; descriptions are kept for the
audit trail but do not by themselves decide a family.

  --family-queue /tmp/opencode/mb_full.csv.zip \

  --family-target 50 --tlsh-threshold 100 --rate 5

listed in `Docs/FAMILY_TREE.md`.
